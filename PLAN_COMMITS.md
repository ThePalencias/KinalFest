# Guía para registrar trabajo real según la rúbrica
No fabriques commits, fechas, autores ni hashes. Registra cada modificación al terminarla y probarla.

1. `feat(db): integrar scripts DDL y relaciones`
2. `feat(db): agregar stored procedures de entidades`
3. `test(db): incorporar datos de prueba`
4. `chore: iniciar proyecto Maven y gitignore`
5. `refactor: organizar paquetes MVC y DAO`
6. `build: configurar JavaFX y JDBC`
7. `feat(core): implementar Conexion singleton`
8. `feat(core): implementar SessionContext`
9. `feat(core): agregar excepciones y logger`
10. `feat(model): crear entidades POJO`
11. `feat(dao): definir interfaces`
12. `feat(dao): implementar CallableStatement`
13. `feat(ui): agregar login y roles`
14. `feat(ui): implementar pantallas CRUD`
15. `feat(ui): agregar proceso transaccional`
16. `chore(git): integrar features a develop`
17. `docs: documentar ejecución y base de datos`
18. `release: preparar versión 1.0.0`
19. `feat(security): revisar validaciones y permisos`
20. `feat(reports): agregar filtros y exportación`
21. `docs: completar documentación técnica`
22. `test: crear y ejecutar pruebas`
23. `refactor: revisar código y errores`
24. `chore: completar checklist de entrega`

**Nota:** El ZIP contiene una instantánea de trabajo. Para asociar un hash a cada tarea, debe existir un cambio real separado que se pueda comprobar. No marques como aprobadas pruebas que no se ejecutaron.
